Build a Decision Tree with LEGO

Every brick is one training example. Its position on the baseplate is the feature x; its colour and print are the label y. A decision tree is nothing more than a stack of yes/no gates, “is x ≤ t?”, chosen one at a time so the trays underneath end up as tidy as possible.

    1

    Build a classification tree

    Pick a threshold to drop the gate between two slots. The bricks fall into two trays. Lower split score = tidier trays. Commit the best one, then click an unfinished branch in the tree and split it too.

    Gate threshold

    More features? Here there is one feature, so “compare splits” means five thresholds. With several features, CART runs this same comparison for every feature and every threshold at each node and keeps the single lowest-scoring (feature, threshold) pair.

    Greedy. CART scores only the two trays directly under this gate. It never looks ahead to ask whether a worse split now would allow a better tree later. Each node is solved on its own, then the bricks move on.

    3

    Build an ensemble

    Ten bricks now sit on a flat plate with two features: column and row . Each of three small trees (depth 2) is grown by CART on its own bootstrap sample. Send one test brick through all three, then let them vote.

    Training plateclick an empty spot to move the test brick

    Why combine? Each tree saw a slightly different pile of bricks, so each one makes different mistakes. When the mistakes differ, they rarely all happen on the same brick, and the vote outvotes them. Averaging regression predictions does the same: errors in opposite directions cancel.

    The catch. If every tree makes the same mistake, voting can’t fix it. Bootstrapping makes the trees differ a little; the random-forest rule makes them differ more by stopping every tree from grabbing the same strongest feature at the top.
