Who Made This Point?

Every point below came from one hidden probability cloud. You never get to see which one. So instead of guessing, the model works out how responsible each cloud is for explaining that point — and that number is the whole idea.

The generative story

  1. First secretly choose a component — component 1 with probability 0.50, component 2 otherwise.
  2. Then generate a point from that component's bell curve.
  3. We observe the point, but not its component. The colour it had is thrown away.
  4. So we compute responsibility: the probability that this component generated the point.

Two things to remember

Responsibility means the probability that this component generated the point — not how close it is, and not a hard label.

Where the distributions overlap, the model is less certain. Those are the washed-out, ringed points — and they are the honest answer, not a failure.

The data never changes as you slide. Only the model's assumptions do. Push the slider right and the weights flatten to 50/50, both covariance matrices collapse to the same small circle, and the only thing left to decide on is raw distance to a centre — which is exactly argmink ‖y − μk‖², the K-means rule. This is addition of densities, not of samples. At every y we add the two shaded heights to get the black curve. We are not adding two draws together — that would give one single bump, not two. Each sample comes from exactly one component.

The two formulas

p(y) = Σk πk · p(y | z = k)

How likely is this point overall? Take each cloud, ask how often it gets picked (πk) times how likely it is to make this point, and add those up.

rk = πk p(y | z = k) ÷ Σj πj p(y | z = j)

Out of all the ways this point could have happened, what share came from cloud k? Top line: this cloud's way. Bottom line: every cloud's way. So the responsibilities always add to 1.

z is the latent variable — the component label that exists but is never seen. μ is the mean , Σ the covariance .
